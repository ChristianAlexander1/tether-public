# TermXPython Handoff (C4a)

Embedded CPython 3.14 for iOS via BeeWare `Python-Apple-support`, in-process `Py_BytesMain` entry (never spawns downloaded native executables), pip bootstrap without fork, and registry manifests for `python3` + `pip`.

## Build instructions

### 1. Fetch `TermXPython.xcframework` (~240MB, not committed)

```bash
cd Packages/TermXPython
./Scripts/build-termx-python-xcframework.sh
```

Outputs:

- `TermX/Frameworks/TermXPython.xcframework` (iOS device + simulator slices; optional macOS slice for host dev)
- `Vendor/TermXPython.xcframework` symlink (SPM binary target)
- `Sources/TermXPythonBridge/PythonHeaders/` (compile-time headers; regenerated by script)

Override tag: `TERMX_PYTHON_SUPPORT_TAG=3.14-b10 ./Scripts/build-termx-python-xcframework.sh`

### 2. Build Swift package

```bash
cd Packages/TermXPython
swift build
```

### 3. Run C4a acceptance tests (iOS Simulator — required)

```bash
./Scripts/run-acceptance-tests.sh
# or specify simulator:
TERMX_IOS_SIM_DEST='platform=iOS Simulator,name=iPhone 17,OS=26.3.1' ./Scripts/run-acceptance-tests.sh
```

Tests read the host-side xcframework path (`TETHER_PYTHON_ROOT`; legacy `TERMX_PYTHON_ROOT` remains accepted) — valid on Simulator; production app bundles the standard library.

## Architecture

```
TermXPython (Swift)
  └─ TermXPythonBridge (C)
       └─ TermXPythonBinary.xcframework  ← BeeWare CPython
```

- **`termx_python_run`**: in-process CLI (`Py_BytesMain`), stdio fd redirect, env/cwd, finalize per invocation
- **`EmbeddedPythonService`**: frozen `PythonRuntime` protocol; serial job queue; `interrupt()` → `PyErr_SetInterrupt`
- **`pip`**: registry alias → `python3 -m pip`; bootstraps from `ensurepip/_bundled/*.whl` (no subprocess — iOS has no fork)
- **Site packages**: `$HOME/python/lib/python3.14/site-packages` via `PYTHONUSERBASE`

## Registry (`Resources/registry.json`)

The registry uses the same command-manifest fields as the host dispatcher:

```json
{ "name": "python3", "kind": "native", "entry": "termx_python_run", "framework": "TermXPython" }
{ "name": "pip",     "kind": "native", "entry": "termx_python_run", "framework": "TermXPython" }
```

## Package installation

- **Pure Python**: PyPI (`https://pypi.org/simple`) — works today (`requests`, `rich`, etc.)
- **Binary wheels (PEP 730 `ios_*`)**: pass a real deployed PEP 503 endpoint to `PythonWheelIndex.pipInstallArgs`; no placeholder Tether service is advertised
- **Optional community source**: the a-Shell aarch64 iOS index (BSD)

## App integrator checklist

1. Link `TermX/Frameworks/TermXPython.xcframework` in the app target (Embed & Sign).
2. Copy `TermXPython.xcframework/lib/python3.14` → App bundle `Resources/python/lib/python3.14` (Briefcase pattern) **or** set `termx_python_set_stdlib_path()` to the bundled path at launch.
3. Set `TETHER_PYTHON_ROOT` only for Simulator/dev — not required on device if stdlib is bundled.
4. Merge `registry.json` into C2 manifest loader.

## Known limitations

- **macOS host `swift test`**: fails without `@rpath` to embedded OpenSSL in the macOS xcframework slice; use iOS Simulator suite above for acceptance.
- **ensurepip**: standard library `ensurepip` uses `subprocess` (fork) — blocked on iOS; use `EmbeddedPythonService.bootstrapPipIfNeeded()` instead.
- **Binary wheels**: not built in this package; index plan + mobile-forge pipeline documented.
- **xcframework size**: too large for git; build script + git-lfs noted in `TermX/Frameworks/README.md`.
